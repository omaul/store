# Фото для витрины

Готовит снимки `scripts/prep-photo.sh`: `sips` ресайзит до 1200 px по длинной
стороне с качеством 85 и пишет копирайт в метаданные. Оригинал не меняется.

## Перед прогоном

- Оригиналы остаются вне git: `originals/` и `temp/` в `.gitignore` — из истории
  публичного репозитория файл потом уже не убрать, даже следующим коммитом.
- Кадр: изделие по центру, фон вырезан или чисто белый, масштаб одинаковый на
  всех снимках одного изделия.
- Тайл в сетке квадратный, но `object-fit: contain` — неквадратный кадр не
  обрежется, а встанет с полями и в ряду будет выглядеть мельче соседей.
- 1200 px не меняем: при открытии тайл разгоняется до 560 px (`MAX_SIZE` в
  `detail.ts`), то есть 1200 закрывает retina ровно.

## Прогон

```bash
mkdir -p public/assets/items/roza    # скрипт папку не создаёт
./scripts/prep-photo.sh "temp/роза/telegram-cloud-photo-1.jpg" roza/roza-front
```

Второй аргумент — путь внутри `items/` без расширения.

- Папка и префикс файла — транслит названия изделия: «звёздочка» →
  `zvezdochka`, «ушной каф» → `ushnoy-kaf`, «сердце» → `serdce`, «абстракция» →
  `abstraktsiya`. Пробелы становятся дефисом, `ё` → `e`.
- Суффикс — ракурс латиницей, как в уже готовых: `front`, `side`, `top`, `hand`,
  `worn`, `ear`, `chain`, `row`, `pair`, `sketch`, `wax`. Второй такой же кадр —
  `-top-2`.
- Если папки нет, `sips` не падает, а пишет снимок в файл
  `public/assets/items/<изделие>` без расширения. Проверь, что появился именно
  `<изделие>/<имя>.jpg`, а не мусорный файл рядом.
- Кадры «в комнате» и раскладки по несколько изделий сразу идут в `lookbook/` —
  это не изделие, в сетку они не попадают.
- `public/assets/COPYRIGHT.txt` лежит уровнем выше и накрывает все подпапки,
  новому изделию отдельный файл не нужен.

## Метаданные

Полная чистка метаданных — только через `exiftool`: он сначала сносит всё, включая
GPS и серийник камеры, и потом пишет копирайт в EXIF, IPTC и XMP. Без него скрипт
уходит в резервную ветку: `sips` пишет один EXIF Copyright, а данные из оригинала
остаются. Для снимков из Telegram это не проблема — там метаданных уже нет; кадры
прямо с камеры или телефона так публиковать нельзя, сначала `brew install exiftool`.

## Подключение

Путь без `public` в `photos` изделия в `src/products.ts`. Первый кадр стоит в
сетке, порядок остальных — порядок листания в карточке. Тексты рядом с фото
(`name`, `sizes`, `note`) — по правилам из skill `typograph`.

## Проверка

```bash
ITEM=roza
sips -g pixelWidth -g pixelHeight -g copyright public/assets/items/$ITEM/*.jpg
mdls -name kMDItemFSName -name kMDItemLatitude -name kMDItemAcquisitionModel public/assets/items/$ITEM/*.jpg
du -h public/assets/items/$ITEM/*.jpg
```

Ждём 1200 px по длинной стороне, копирайт на месте, координаты и модель камеры
пустые. Вес сравни с готовыми снимками — они в диапазоне 130–330 КБ, заметно
тяжелее значит пережать. Потом `npm run build`.
